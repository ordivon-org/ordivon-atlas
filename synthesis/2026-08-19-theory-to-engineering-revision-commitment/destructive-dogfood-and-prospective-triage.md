## 1. Four-case destructive calibration

### Case A — Network `Communicability -> InterLocusCapability`

Classification after destructive review:

- failure locus: `REPRESENTATION / SEMANTIC DECOMPOSITION`;
- revision depth: approximately `L3`;
- reason: the Bell/joint relational-resource counterexample attacked Communicability as the universal carrier itself, not merely a parameter inside a stable carrier model;
- expected consequence of a true carrier repair: downstream composition semantics should also need repair and old/current authority-version statements must remain distinct;
- observed history was compatible with that prediction: NDF0 repair propagated into NDF1 composition repair while historical statements were preserved rather than rewritten.

Important restraint:

This demonstrates a strong owner-native representation repair case. It does **not** establish an independent general finite-intelligence theory; ordinary scientific concept repair plus versioned owner history may fully explain the episode.

### Case B — Computing HD8 shallow -> thick historical evidence

Classification:

- failure locus: `CONTACT / EVIDENCE-REPRESENTATION FIDELITY`;
- **not** strong ontology/representation escape.

The programme kept substantially the same historical trajectory coordinates while replacing shallow packets with thick causal trajectories. Blind judgments changed materially (61/120), agreement increased and `INSUFFICIENT` decreased.

This is a destructive guard against framework overreach:

`Evidence representation/contact fidelity != ontology revision`.

A framework that calls every large judgment change `Representation Escape` fails this control.

### Case C — Research-System stale READY

Classification:

- failure locus: `STANDING / CURRENTNESS`;
- revision depth: `L1` reconciliation;
- no ontology redesign required.

The destructive fixture established:

`HostReady != SemanticCurrent`.

Historical READY remains valid continuity evidence, while current semantic resumption must recover the later owner authority. Recovery does not mint authority.

This is the low-revision-depth control: a general framework must be able to say `this is just currentness`.

### Case D — root/destructive-safety observation

Classification:

- locus: `COMMITMENT / ADMISSION` for the synthetic mechanism;
- epistemic revision required for the synthetic fixture: none beyond current evidence.

A LIGHT disposable deletion executed with exact standing/precondition/effect/postcondition evidence. A FULL_BLOCK candidate with unresolved mutable state was not admitted; exact clientRequestId had no Runtime Job.

This supports the mechanism-level separation:

`Capability != Admission/Commitment`.

It does **not** establish the longitudinal causal claim that this mechanism explains the historical absence of known catastrophic unrecoverable loss. Human supervision, workload mix, Git/recoverability, exposure, architecture and sampling remain rival explanations.

## 2. Main dogfood repair

The four cases forced a distinction the earlier linear revision ladder did not capture:

`FailureLocus != RevisionDepth`.

Useful loci include:

- Contact / observation / evidence fidelity;
- Standing / currentness / provenance;
- Mechanism / local theory;
- Representation / semantic decomposition;
- Commitment / admission / effect mediation;
- mixed cases when a real fixture proves interaction.

Only after localization should minimal revision depth be selected.

The durable judgment compression became:

`FailureLocalization + MinimalRevisionSelection + CommitmentCalibration`.

Later this was shortened operationally to:

`Locate -> ReviseMinimally -> CommitProportionally`.

## 4. v1 design failure: leakage

The v1 design itself exposed a methodological flaw before outcomes could be used as validation.

The checkpoint previews shown to the predictor already contained owner `frontier` / `nextActions`. Therefore a correct `NextOperator` forecast could simply echo owner-local reasoning.

Result:

- v1 remains useful for calibration failures such as over-escalation, wrong locus or commitment-ceiling violation;
- v1 `NextOperator` correctness cannot establish incremental predictive advantage;
- predictions remain frozen and may not be retrofitted.

This is important process evidence: the experiment was downgraded instead of being defended after its leakage was discovered.

## 5. Blind-input v2 protocol

A stricter future protocol was frozen.

### Input packet

May contain:

- task objective;
- exact raw trigger/evidence/provenance needed to understand the anomaly;
- pre-existing stable constraints;
- exact pre-resolution source fence.

Must exclude:

- owner diagnosis;
- final theory/standing conclusion;
- proposed repair;
- `nextActions`;
- desired framework label;
- desired baseline label.

### Symmetric outputs

Both the framework and `OWNER-LOCAL-FIRST` must produce:

- FailureLocus;
- MinimalRevisionDepth (`L0` no-change through `L4` meta-representation);
- one NextOperatorFamily;
- CommitmentCeiling;
- explicit falsifier.

### Outcome discipline

Only a later material owner resolution after the packet fence counts.

`READY persistence`, task completion alone, Host continuity or Atlas projection do not count as semantic outcomes.

### Controls

A useful sample must include at least:

- local/currentness/contact-only case;
- genuine representation-pressure case;
- mechanism/theory case;
- null/no-change case.

This is necessary to estimate over-escalation pressure rather than reward theoretical depth.
