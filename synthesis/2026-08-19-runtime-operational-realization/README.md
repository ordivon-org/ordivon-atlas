## What the programme learned

### C1 — Currentness is typed, not Git recency

A first naive rule treated publication `sourceRevision != Git HEAD` as staleness. Real owner-authority/currentness evidence falsified that rule.

Surviving distinction:

```text
Host continuity currentness
!= transport/Git recency
!= owner AuthorityVersion currentness
!= publication source horizon
```

Historical validity can survive while current standing changes.

### C2 — Retry is a new admission decision

Local timeout/failure does not directly authorize rerun.

Safe continuation requires:

```text
EffectKnowledge
+ OperationStanding
+ OperationContract
```

with authoritative reconciliation when external effect is unknown.

### C3 — Fresh execution is not always necessary

Exact replay of the same durable Operation may reuse retained realization without a fresh Attempt.

But equal command text or operationDigest across distinct Operations does not establish semantic discharge.

Bounded formula:

`FreshExecutionNeed = UnsatisfiedAdmissibleSupportGap`.

Generic cross-Operation support equivalence remains unproven and likely requires explicit Runtime↔SCD support semantics.

### C4 — Standing / Currentness exceeds Runtime ownership

The C1 relation reproduced for Network inside a shared physical research corpus. This crossed the threshold for `Standing / Currentness Semantics` to become an independent research-programme candidate.

The export did not remove Runtime's owner-native lifecycle/standing semantics.

### C5 — Evidence support is typed, not scalar

Strong evidence from Runtime + Host + owner publication + Atlas does not fill a missing semantic support type.

Core rule:

```text
ClaimAdmissible(C)
iff RequiredTypedSupport(C) is covered by proven support/bridges
```

More evidence does not manufacture a missing authority/scope relation.

### C6 — End-to-end success is composed, not atomic

A real publication chain admitted meaningful intermediate states:

```text
LOCAL_ONLY
DELIVERY_UNKNOWN
OWNER_PUBLISHED_DOWNSTREAM_STALE
PIPELINE_CONVERGED
```

Even final convergence is a supported composed claim, not evidence of one cross-system atomic transaction.

### C7 — Retry-like continuation may cross Runtime Operation identity

The exact Branch-H ledger corrected an explanatory simplification. HTTPS push, reconciliation, SSH push and final verification were distinct Runtime Jobs/Operations/Attempts under one higher-level publication obligation.

Therefore:

```text
same higher-level obligation
!= same Runtime Operation
!= same Attempt
```

Bounded causal attribution required pre-state absence + attempt-specific transition evidence + post-state presence.

### C8 — Capability / Authority / Binding / Realization are orthogonal

Live Workstation evidence showed capability/profile identity may exist while realization is unavailable or unknown.

Required distinctions:

```text
Capability != Authority
Authority != Realization
Binding != Realization
SemanticIdentity != PhysicalRealization
IdentityContinuity != PositiveStanding
```
