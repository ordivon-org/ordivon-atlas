# Runtime C1–C10 Anti-Rediscovery Guard

## Purpose

Before opening fresh Runtime theory work, search the Runtime owner publication/corpus and this synthesis/process-lineage collection for equivalent prior results.

This guard prevents future Agents from re-deriving already falsified shortcuts or reopening saturated routes merely because the exact wording differs.

## Must not be rediscovered as fresh theory

### 1. Git recency as semantic currentness

Rejected shortcut:

`publication.sourceRevision != latest Git HEAD => semantic stale`.

Current result: owner AuthorityVersion/currentness, transport observation and publication source horizon are distinct typed roles.

### 2. Local failure directly authorizes retry

Rejected shortcut:

`timeout/error -> retry`.

Current result: retry-like continuation is a fresh admission decision after effect knowledge and standing are re-grounded.

### 3. Same command/digest means interchangeable support

Rejected shortcut:

`same command` or `same operationDigest` across distinct Operations -> historical result can discharge the new obligation.

Current result: exact same-Operation replay is safe; generic cross-Operation semantic support reuse is not established.

### 4. Evidence quantity substitutes for evidence type

Rejected shortcut:

`many strong evidence objects -> broader truth`.

Current result: missing typed support/authority cannot be filled by accumulating unrelated evidence.

### 5. One global success bit represents a publication pipeline

Rejected shortcut:

`publicationSucceeded=true` describes local commit, remote delivery, owner currentness and downstream freshness.

Current result: these are distinct staged claims connected by explicit bridges.

### 6. Retry necessarily means same Runtime Operation + next Attempt

Rejected shortcut:

`retry = same Operation, Attempt n+1`.

Current result: retry-like continuation may preserve a higher-level obligation while using a new Runtime Operation when binding/provider/transport changes.

### 7. Post-state observation alone proves causation

Rejected shortcut:

`target state observed after A2 -> A2 caused it`.

Current result: bounded causal attribution needs an evidence chain such as pre-state absence + attempt-specific transition evidence + post-state presence.

### 8. Capability / authority / binding / realization collapse

Rejected shortcuts:

```text
available capability -> authorized
configured authority/profile -> active realization
selected binding -> realized outcome
historical identity -> positive standing
```

Current result: these are orthogonal admission axes.

### 9. Reclamation means historical erasure

Rejected shortcut:

`workspace removed -> its Job/Attempt/artifact history no longer exists`.

Current result: physical substrate reclamation and historical evidence retention are separate lifecycle dimensions.

### 10. Saturation implies exhaustive closure

Rejected shortcut:

`C1-C10 saturated -> Runtime fully/exhaustively solved`.

Current result:

```text
ProgrammeSaturated(current evidence horizon) = true
WholeRuntimeExhaustiveClosure = UNKNOWN
```

### 11. Saturation automatically continues as C11

Rejected route:

`C10 complete -> open C11 because more theory could always be studied`.

Current result: no automatic C11. A concrete new falsifier satisfying the Runtime programme Constitution/R1–R8 is required.

### 12. Cross-owner Standing result should be reabsorbed into Runtime

Rejected route:

`Standing/Currentness is useful to Runtime -> Runtime owns all currentness semantics`.

Current result: Runtime retains owner-native lifecycle standing; the broader Standing/Currentness abstraction was exported as an independent research-programme candidate.
