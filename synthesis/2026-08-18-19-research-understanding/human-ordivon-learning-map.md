# Human–Ordivon Learning Map v1

## Status

`HUMAN_CONSUMPTION_GUIDE`

This is a Human-facing consumption model derived from the research review. It is **not** a new Human Foundation and does not claim Human-owner semantic authority.

## Problem

As Ordivon research grows, a human cannot and should not try to memorize every Foundation, branch, artifact, digest, experiment, and historical repair. Optimizing only machine research throughput would leave the human operator unable to understand or steer the resulting system.

The goal is therefore not Human knowledge-volume parity with Ordivon. It is **human command of the smallest stable conceptual/judgment layer needed to steer and audit a much larger retrievable research system**.

## Four layers

### L1 — Human Core

Permanently internalize a small set of high-value distinctions and judgment rules.

Current candidate core:

1. `Reality != Representation`
2. `Evidence != Conclusion`
3. `Structure != Meaning`
4. `Attempt != Possibility`
5. `Task != Run != Attempt`
6. `Intent != Effect != Result`
7. `History != Currentness`
8. `Recovery != Re-admission`
9. `Owner = Truth Responsibility`
10. `Important != Foundation != Project != Service`
11. `Agent-first = Falsification/Stress Regime`
12. `Wide Interior / Narrow Consequence Boundary`

Mastery means being able to detect a category error in a fresh concrete case, not reciting terminology.

### L2 — Working Knowledge

Understand concepts well enough to recognize when they apply and reason with them during active work. Examples:

- SCD equivalence/refinement/preservation
- Computational Regime / witness / reduction
- Runtime UNKNOWN effect reconciliation
- Host revision/lease/continuity boundaries
- Harness Context/Tool/run boundaries
- source fence/currentness/authority
- destructive falsification
- minimal repair
- typed negative results
- scoped closure

### L3 — Retrievable Knowledge

Know that detailed research exists and know how to find it, but do not keep it permanently loaded.

Examples:

- numbered Foundation registries
- detailed derived architectures
- specialist falsifiers
- owner genealogies
- exact cross-owner bridge details

Atlas and owner corpora should make this tier cheap to recover.

### L4 — Machine Memory

Actively externalize exact operational/history detail:

- Git commit IDs
- AuthorityVersionRef digests
- branch/worktree names
- Task revisions
- artifact hashes
- full evidence matrices
- exact historical registry rows

The human should understand **what role these identifiers play**, not memorize their values.

## Human responsibilities that should remain hard to outsource

At current maturity, retain strong human involvement in:

- long-horizon direction/value judgment;
- importance judgment (true does not imply important);
- architecture taste and detection of structure inflation;
- consequential-action judgment;
- meta-skepticism about Ordivon's own methods and self-reinforcing abstractions.

This does not mean Agents cannot assist or outperform the human on candidate generation. It means these consequence/value/admission judgments should not be silently inferred from machine scale alone.

## What should be aggressively externalized

- search and discovery;
- provenance/digest tracking;
- repetitive verification;
- negative-history retrieval;
- context reconstruction from durable owner sources;
- mechanical comparison and source-fence checks.

## Human admission test for new research

When new research appears, ask:

1. Does it alter the human's basic model of reality/knowledge/action? -> candidate L1.
2. Will it repeatedly affect current judgment/work? -> L2.
3. Is it specialist/domain detail needed only on demand? -> L3.
4. Is it exact operational/provenance detail? -> L4.

This prevents Ordivon growth from linearly increasing human cognitive load.
