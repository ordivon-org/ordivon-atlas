# Anti-Rediscovery Guard v0

## Status

`NEW_CROSS_OWNER_SYNTHESIS`

Purpose: prevent Ordivon from repeatedly rediscovering already-known results merely because the prior result lives in a different owner, old Task, negative history, Computer Knowledge document, or conversation-derived synthesis.

## Pre-research check

Before admitting a fresh research route, perform a bounded prior-result lookup across:

1. **Atlas** — owner map, current results, closure, negative/lineage history, recovery/currentness pointers.
2. **Current owner corpus/publication** — authoritative domain semantics and current source fence.
3. **Computer Knowledge / cross-owner synthesis** — reusable methods, prior cross-project conclusions, world-model links.
4. **Typed negative history** — falsified, not-admitted, reduced, baseline-equivalent, no-effect and repair-required routes.
5. **Curated Atlas synthesis** — explanatory/prior-result compression such as this directory; useful for discovery but not semantic authority.

## Classification before opening a new route

A candidate question should be classified as one of:

- `NEW_QUESTION` — no semantically equivalent prior result was found within the bounded search.
- `SEMANTICALLY_EXISTING` — the question/result already exists; consume or revalidate it instead of rediscovering it.
- `HISTORICAL_OR_SUPERSEDED` — a prior result exists but is not current; recover genealogy and start from the current owner state.
- `REPAIR_OF_EXISTING` — new evidence attacks a specific current claim; open a repair path rather than a parallel duplicate theory.
- `CROSS_OWNER_SYNTHESIS_NEEDED` — owner results exist but the missing value is their comparison/compression, not new domain research.
- `CURRENTNESS_UNKNOWN` — sources cannot establish current status; resolve currentness before treating the question as fresh.

## Duplicate test

Do not compare only names. Two differently named questions may be semantically the same; one reused term may hide a materially different obligation/regime/owner scope.

The lookup should compare, as available:

- proposition/question meaning;
- owner/truth responsibility;
- scope/regime;
- evidence/falsifier class;
- claimed standing;
- source fence/currentness;
- reopen condition.

## Safety laws

- `SameLabel != SameQuestion`
- `DifferentLabel != NewQuestion`
- `Recovery != Currentness`
- `AtlasHit != OwnerTruth`
- `PriorFailure != PermanentProhibition`

Negative results must retain scope and reopen conditions so anti-rediscovery does not become anti-research dogma.

## Intended future automation

Atlas/Lab may later automate candidate retrieval, semantic-neighbor search, source-fence checks and duplicate warnings. Automation should return **prior-result candidates and currentness health**, not automatically reject research or mint semantic equivalence.
