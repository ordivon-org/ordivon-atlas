## What an owner means

An Ordivon semantic owner is not defined by repository location or by which system stores a record.

The useful question is:

> **Who owns the truth conditions for this kind of claim?**

A single real event can legitimately have several owner-relative projections because the owners answer different questions.

Example: an Agent submits a financial order.

- **World** — what external event/observation occurred?
- **Finance** — what financial claim, order, position or settlement state resulted?
- **Normative** — was the action authorized/valid in the relevant rule context?
- **Runtime** — what physical execution attempt actually ran?
- **Harness** — how did the bounded Agent cognition/Tool interaction proceed?
- **Host** — what did this change about the long-lived Task?
- **Human** — how does the action relate to the person's objective, preference or decision participation?

These are not competing copies of one mutable truth.

## World is foundational but deliberately thin

World owns generic Reality concerns such as existence, change, possibility, causal structure, property evaluation and temporal structure. It does **not** become an Everything Ontology.

Domain owners retain irreducible truth conditions that generic Reality cannot safely define for them.

| Owner | Human mental handle | Examples of irreducible concern |
|---|---|---|
| World | generic Reality | existence, change, causality, property evaluation, temporal structure |
| Human | person | belief, preference, agency, experience, learning, participation |
| Finance | claim | positions, obligations, control, settlement, liquidity, financial mechanisms |
| Game | ludic reality | constituted game state, participation, valid transition, challenge/progress |
| Media | representation | capture, expression, framing, legibility, metricization, interpretation |
| Network | inter-locus capability | capability across loci, reachability, resolution, forwarding, service/topology |
| Ordivon Normative | validity | admission, permission, obligation, competence, consequence/transformation semantics |

The guiding law is:

`SameReality != SameTruthQuestion`

## Owner admission is not reality admission

A phenomenon can be real or important without earning an independent semantic owner.

Current canonical examples include AgentialOrganization, Phenomenality-related interface work, Normative Support and persistent purposive coordination. Their failure/non-admission as independent owners does not imply that the underlying realities are false.

`OwnerFailure != RealityFailure`

Possible placements for important non-owner results include:

- owner-internal derived architecture;
- cross-owner bridge;
- historical/contested interface;
- Computer cross-owner synthesis.

## Thin topology rule

Do not create an owner because a noun is important. Consider a new owner only when there is sustained evidence of an irreducible truth responsibility that existing owners cannot preserve without semantic loss.

This supports a target shape of:

`thin owner topology + rich derived architectures + typed cross-owner bridges`

rather than `one concept -> one owner/repo/service`.
