# Anti-Rediscovery — Cross-Owner Coupling Audit v1

## Do not rediscover as a new global architecture

Current evidence does **not** admit:

- a Global Core because several owners reuse similar words;
- a horizontal Identity / State / Event / Graph / Policy / Memory / Capability / Effect / Lifecycle layer;
- an exhaustive owner registry in Computing or Atlas;
- a universal representation/projection owner;
- a global relation/predicate ontology;
- a central Action Admission owner;
- PAL/RSI rehoming by cross-project recurrence alone;
- Host ownership of generic task grading / Q-C-A-U semantics;
- repository migration merely because a semantic programme became independent.

## Stable distinctions to recover first

`Repository != SemanticOwner != ImplementationOwner != PersistenceCarrier != AuthorityIssuer != EvidenceCustodian != ProjectionPublisher`

`ImplementationCoupling != SemanticAuthorityCoupling`

`HistoricalIdentity != CurrentIdentity`

`HistoricalObservation != CurrentOwnerStanding`

`Recovery != Authority`

`CarrierSuccess != DomainSuccess`

`SHARE_RELATION != MOVE_INSTANCE_TRUTH`

`IndependentProgramme != ProductionServiceAdmission`

## When a shared layer may be justified

Use the existing thin-core criterion rather than vocabulary symmetry.

Permanent shared structure should be reserved for a **non-bypassable responsibility that survives materially different workloads**. Owner-native substantive predicates should remain external/extensible whenever possible.

Branch E / Atlas identity-authority-currentness-provenance grammar is a positive control: heterogeneous owners share a thin control grammar without centralizing domain truth.

A relation/view/convenience surface does not meet that bar merely because it reduces one Agent’s file-reading burden.

## Rehome gate

Do not rehome research or implementation until all are true:

1. the responsibility recurs across materially different owners/workloads;
2. deletion from the historical home exposes a real owner/authority mismatch;
3. the surviving responsibility is independently falsifiable and consumer-relevant;
4. relocation does not merely copy or normalize owner-native truth;
5. source authority, currentness and recovery remain explicit.

If these are not satisfied, prefer `KEEP_LOCAL`, `SHARE_RELATION`, a bounded carrier ceiling, or a derived bridge.

## Computing registry repair guard

Do not restore `projects/registry.yaml` as global/current semantic-owner identity authority.

Current Computing packaging follows **Media**. Historical `ordivon-studio` observations and CLI/package/tool identities remain valid in their own source-fenced roles.

Never infer:

`StudioHistoricalObservation -> MediaCurrentAssimilation`

Never infer:

`MissingStudioCheckout -> Media/StudioOwnerAbsent`

A future Media world-model observation requires a fresh exact observation/research action; this closeout does not manufacture one.

## Reopen only from evidence

Reopen this audit only when a named natural consumer or owner boundary demonstrates a concrete failure such as:

- a carrier repeatedly lifts a local status into another owner’s standing despite current semantic ceilings;
- the same deletion-essential relation is independently reimplemented across heterogeneous consumers and local/generated handling no longer suffices;
- a current semantic responsibility is demonstrably trapped in the wrong historical home;
- a new owner transition makes current identity/currentness unrecoverable through owner-native + Atlas surfaces.

Do not reopen because a diagram has an empty layer or because a cross-cutting noun appears often.
