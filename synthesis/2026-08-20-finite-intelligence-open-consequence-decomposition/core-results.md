# Core Incremental Results

## 1. Future-consequence sufficiency

For continuation family `Gamma`, define `x equiv_Gamma x'` iff all allowed continuation outcome laws agree. Representation `R` is exactly `Gamma`-sufficient when `ker(R) subseteq equiv_Gamma`.

Preserve:

- `CurrentTaskIrrelevance != FutureIrrelevance`
- `PredictiveSufficiency != InterventionalSufficiency`
- `Compression != IrrelevanceProof`
- expanding `Gamma` can only split safe equivalence classes.

If future tasks are unrestricted, any merged pair can be made consequential by some future task; therefore no nontrivial lossy representation is universally safe except modulo full physically admissible continuation equivalence.

## 2. Open relevance / consequence basis

Preserve:

- `DynamicPreference != DynamicObjectiveBasis`
- `PreferenceUncertainty != RelevanceVocabularyUncertainty`
- `WhatCanHappen != WhatCanBeDone != WhatMatters`
- `AffordanceDiscovery != GoalDiscovery`
- `Controllability != Consequentiality`

If every future task/relevance functional factors only through the current representation, it cannot make distinctions already collapsed by that representation consequential. Utility-gated exploration can therefore self-seal relevance discovery.

## 3. Revelation, activation and generation

Future problems/consequences are not all pre-existing unknowns.

- **Revelation:** consequential relation already exists and is newly observed/represented.
- **Activation:** a latent distinction becomes consequential because a new action/capability/context makes it reachable.
- **Generation:** an intervention, technology, institution, metric or deployed representation changes causal/strategic/selection structure and creates new consequence classes.

Hence:

- `ProblemDiscovery != ProblemActivation != ProblemGeneration`
- `ConsequenceAbsence != ConsequenceInaccessibility`
- `ObservedRegularity != PreexistingRegularity`
- `CurrentWorldUnknown != NotYetRealFutureUnknown`

## 4. Capability growth can create endogenous epistemic/governance debt

Separate at least:

- generative/reachable-regime frontier,
- observability/recognition frontier,
- discrimination/challenge frontier,
- response/repair frontier.

A system can improve absolutely on all while its relative uncovered frontier grows. Requisite response is typed: variety alone is insufficient; latency, scale, locality, attribution, observability and reversibility matter.

Preserve:

- `AbsoluteIntelligenceGrowth != RelativeEpistemicCoverageGrowth`
- `CapabilityMagnitude != CapabilityGenerativity`
- `Detection != Diagnosis != Repair`
- `ResponseVariety != EffectiveRequisiteVariety`
- `CoverageFraction != AdaptiveAdequacy`

Combinatorial capability growth makes exhaustive outcome validation non-scalable; structural/compositional compression of challenge obligations is required when possible.

## 5. Standing compositionality

`St(A), St(B)` does not imply `St(A o B)`.

Composition requires, at minimum:

1. local warrant preservation,
2. assumption discharge,
3. interface sufficiency for the global property/context family,
4. validity of the composition rule,
5. adequacy of shared-substrate/context modeling.

Preserve:

- `ComponentVerification != UnconditionalSubstitutability`
- `ProofSoundness != ModelAdequacy`
- `NodeVerification != SeamVerification`
- `PairwiseInteractionStanding != HigherOrderInteractionStanding`

A useful modular decomposition exists when consequential cross-boundary behavior factors through interfaces substantially smaller than component interiors.

## 6. Open-world interface challenge

Finite tests cannot certify unrestricted interface sufficiency. A relative interface claim must be scoped to target properties, intervention/context families and structural assumptions.

Useful falsification operators include holding the declared interface fixed while varying hidden context, cross-context invariance, implementation substitution, shared-resource stress, simultaneous faults/load, residual-dependence search and historical/cross-domain seam-breaker import.

Preserve:

- `FiniteTestPass != OpenWorldInterfaceSufficiency`
- `TestCount != LatentCouplingCoverage`
- `ObservedInvariance != LatentVariableAbsence`
- `AssumptionMonitoring != AssumptionDiscovery`
- `SingleFactorStressCoverage != InteractionCoverage`

## 7. Missing interface vs wrong decomposition

For decomposition `D`, use a conceptual repair curve `L_D*(c)`: minimum consequential leakage achievable with interface complexity budget `c`.

- **Missing interface:** leakage falls quickly after a small interface refinement.
- **Wrong decomposition:** leakage falls only when boundary complexity approaches interior complexity, or repeated repair remains nonlocal/high-cost.
- **Intrinsic nondecomposability relative to target:** no plausible partition has a favorable repair curve.

Pressure includes interface inflation, intervention nonlocality, higher-order interaction leakage, long history requirements, substitution-failure density, update nonlocality and large standing blast radius.

Preserve:

- `CrossBoundaryInteraction != BadDecomposition`
- `LowCoupling != CompositionalLeverage`
- `ShortHorizonModularity != LongHorizonModularity`
- `LocalFailure != StructuralFailure`

## 8. Decomposition plurality and transport

Multiple locally useful decompositions need not admit a low-cost master partition.

- common refinement preserves all distinctions but can grow combinatorially/exponentially;
- common coarse consensus can erase complementary structure and even collapse to one block.

A claim in decomposition `Di` transports to `Dj` only if its Reality content factors through `Dj`. Causal/standing transport additionally requires interventional and warrant/challenge consistency.

Preserve:

- `DecompositionLocal != EpistemicallyInferior`
- `DecompositionAgreement != IndependentEvidence`
- `AnalyticalRedecomposition != ArchitecturalRefactoring`
- `DecompositionDisagreement != SchemaConflict`

## 9. Diagnostic boundary rotation

Alternative decompositions can be temporary breakers rather than permanent ontologies.

- `OperationalDecomposition != DiagnosticDecomposition`
- `UsefulBreakerDecomposition != AdequateOntology`
- `BoundaryRotation != BoundaryBreaker` unless it generates a materialized probe and Reality uptake.

For `n` declared loci and `m` `k`-way diagnostic cuts, each locus has a signature in `[k]^m`. Every pair is separated by at least one cut iff signatures are injective; thus complete pairwise boundary exposure requires and can be achieved with:

`m >= ceil(log_k n)`.

This is pairwise seam exposure only, not interaction discovery, higher-order coverage, correct primitive vocabulary or open-world completeness.

Pressure-guided cuts require a pressure-independent/lineage-orthogonal escape complement because current pressure maps can self-seal.

## 10. Locus formation beyond object-first representations

A candidate locus can be provisionally written `phi(H)->Z`, with rich retained substrate/history `H`. Candidate loci may be object properties, relations, temporal/process summaries, events, collective modes or fields.

Preserve:

- relation/process structures can often be reified as nodes/states without gaining independent causal semantics;
- `Nodehood != IndependentObjecthood`;
- `PredictiveUtility != ObjectStanding`;
- `VariableCanBeComputed != VariableHasWellDefinedIntervention`;
- `LocusDiscovery != LocusTyping`;
- instantaneous feature generators cannot repair genuine history aliasing;
- objectwise feature generation need not provide relational expressivity;
- `FunctionClassRichness != LocusTypeRichness`.

Candidate locus standing should remain an operation profile: predictive/interventional leverage, cross-context transport, compression/state closure, autonomy/coherence and provenance/re-entry.

## 11. Current frontier: support search

Candidate generation is now better treated as `(S,phi)`, where support/scope `S` may span entities, time windows, populations, spatial regions, interaction order or scales.

The unresolved tension is:

`Locality/Sparsity/TimescaleSeparation -> tractability`

versus

`AssumingLocality/Sparsity -> possible blindness to long-range/high-order/cross-scale consequential structure`.

Do not retreat to partition search or object discovery as if `S` were already given.
