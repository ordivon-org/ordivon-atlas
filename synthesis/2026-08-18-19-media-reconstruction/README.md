## Why this synthesis exists

The final Media repository now states the correct owner boundaries, but several durable insights are easy to lose if future recovery reads only current end-state documents:

1. why the project changed from Studio-first to Media-first;
2. why many important Media concepts did **not** become MF10;
3. why Web and Game must remain autonomous despite heavy Media consumption;
4. why a Media projection discipline is broader than creative-media tooling or UI;
5. why repeated dogfood strengthened OMPC through new invariants without forcing new primitive roles or shared code;
6. why the correct Phase-1 conclusion was to **stop default construction** and wait for real consumer pressure.

Re-deriving these points would require traversing Media research, project-formation commits, multiple Host closeouts, Web/Finance evidence and the explanatory conversation again. This file keeps the minimum cross-document compression needed to avoid that repetition.

## 1. The central owner inversion

The old practical/project picture was approximately:

```text
Ordivon Studio
  -> writing / image / audio / video / interactive / 3D / production
  -> Media research nested inside
```

The research result forced the opposite semantic relation:

```text
Ordivon Media
  -> Studio authoring / production capability plane
```

The reason was not naming preference. Media research had expanded from artifact categories into **structured mediation**: signal, perception, representation, composition, spatial/temporal organization, state/dynamics, agency and experience. Studio is only one way of constructing mediated structures; it cannot plausibly own publication standing, mediated presence, interface relations, audience/visibility, preservation identity, infrastructure roles or datafication/legibility.

Anti-rediscovery guard:

`StudioIsTopLevelMediaOwner = REJECTED`.

Current recovery:

- Media = semantic/project owner;
- Studio = retained active authoring/production capability;
- existing `ordivon-studio` CLI/package/tool names may remain valid capability identities.

## 2. MF0–MF9 are an architecture, not a media-type inventory

A recurring failure mode is to reconstruct Media from carrier/product categories such as text, image, audio, video, interactive and 3D. Those categories remain useful production/consumer regimes, but they are not the current Foundation architecture.

The stronger compression is:

```text
Reality / Source
  -> mediation / signal
  -> perception / accessibility
  -> representation
  -> composition
  -> space / time
  -> state / dynamics
  -> agency
  -> experience
```

This is explanatory structure, not a mandatory linear implementation pipeline.

Anti-rediscovery guard:

`M7ProductionRegimes == MediaFoundations` is false.

Also:

`MF0–MF9 != software module map`.

## 3. Important does not imply primitive

A major research lesson was learned by **refusing MF10** despite many important candidates.

Concepts such as:

- communication;
- protocol;
- publication;
- work/edition/variant;
- authorship;
- audience/public;
- selection/curation/recommendation;
- translation/remediation;
- archive/preservation;
- infrastructure/environmental media;
- executable/operative media;
- interface/affordance;
- telepresence/distributed embodiment;
- datafication/legibility/metricization;

survived as scientifically/operationally real but reducible/cross-owner structures.

The durable law is:

`NONPRIMITIVE != UNREAL`.

A candidate becomes a Foundation only if it contributes a genuinely irreducible Media responsibility after destructive reducibility and neighboring-owner tests. Product importance, frequency of use, cultural prominence or engineering convenience are insufficient.

Useful synthesis:

```text
Foundation relations
+ cross-owner facts
+ typed composition
-> Derived Media phenomenon
```

Examples:

```text
Publication ~= Exposure + Access + Audience Scope + Standing
Interface ~= Representation + Perception + Action Exposure + Mapping + Feedback
Telepresence ~= Remote Access + Space/Time Coupling + Agency + Experience
Legibility ~= Representation + Aggregation + Query/Consumer Perspective + Capability
```

These are explanatory decompositions, not canonical equations or implementation schemas.

Anti-rediscovery guards:

- `InterfaceNeedsMF10 = REJECTED`
- `PublicationNeedsMF10 = REJECTED`
- `PresenceNeedsMF10 = REJECTED`
- `DataficationOrLegibilityNeedsMF10 = REJECTED`

## 4. Web and Game boundary corrections

### Game

The strongest boundary is:

`Game != InteractiveMedia`.

Game owns ludic constitution, action/control/skill, challenge/failure/mastery and authoritative case determination. Media owns how Game truth/action is represented, perceived, exposed, temporally/spatially organized and fed back.

A useful recovery sentence is:

> Game owns what the ludic system/action means; Media owns how it is mediated; Runtime owns what actually executes; Human owns the relevant human cognitive/experiential truth.

Therefore Game remains an autonomous owner and Media consumer/bridge.

### Web

The conversation initially entertained putting Web more directly under Media because Web can realize nearly the full Media stack. That was later narrowed.

Web is indeed a powerful Media realization environment, but it also serves Host, Runtime, Research, Finance and the whole Ordivon interface/public surface. Making it a Media-owned universal frontend would create a new ownership distortion.

Current synthesis:

```text
Media <-> Web
```

not:

```text
Media
  -> Web as semantic child owner
```

Physical repository containment is also independent from semantic dependency.

Anti-rediscovery guards:

- `WebIsJustAMediaSubtype = REJECTED`
- `WebMustBePhysicallyMergedIntoMedia = REJECTED`
- `GameShouldBeAbsorbedByMedia = REJECTED`

## 5. Media became broader than creative tooling

The Media project acquired a broader Ordivon role when source-owned truths were treated as mediated observations/projections for humans and Agents.

Examples:

- Host Task truth -> Human/Web projection or Agent structured projection;
- Runtime state -> status/timeline/interaction surface;
- Atlas research space -> maps/graphs/matrices without Atlas presentation becoming owner truth;
- Finance facts -> metrics/dashboards without the visible metric becoming financial truth;
- Game state -> mediated player/Agent perception and action feedback.

This led to the key project law:

`Projection != SourceAuthority`.

Media owns the semantics of presentation/mediation relations. It does not become a second mutable truth store for the domain being displayed.

## 6. OMPC was earned by falsification, not designed as a universal schema

Phase 1 introduced the technology-neutral Ordivon Media Projection Contract (OMPC-v0). Its six role families survived four materially different consumer fixtures:

- A — Host continuity/currentness projection;
- B — Studio transformation/provenance/identity;
- C — Web temporal interaction trajectory;
- D — Finance metric/proxy/legibility.

The important process result is that dogfood repeatedly added **invariants**, not new primitive roles.

Examples of evidence-driven refinements:

- Studio SVG/PNG lineage -> Identity Non-Collapse;
- Web initial/final-equivalent but trajectory-different interaction -> Temporal Coverage Non-Collapse;
- Finance unchanged headline metrics but changed owner decision after execution-context evidence -> Metric / Proxy Non-Collapse.

This is evidence that the six-role decomposition retained compression power across heterogeneous consumers.

Anti-rediscovery guard:

`OMPCConformance == ProductionSchema` is false.

Also:

`RepeatedSemanticPressure != SharedImplementationPressure`.

No Media Engine, Runtime, SDK, universal OMPC serializer or validator service was admitted in Phase 1.

## 7. Three concrete anti-lifting lessons

The conversation repeatedly discovered the same structural error in different forms.

### State lifting

`DisplayedState != Runtime/DomainState`.

A success badge or UI state cannot substitute for committed source-owner effect.

### Temporal lifting

`SameInitial + SameFinal != SameEncounter`.

Transient feedback, latency and recovery trajectory can carry material meaning.

### Metric lifting

`NumericallyTrueMetric != SemanticallySufficientDecisionProjection`.

Finance Fixture D showed unchanged headline metrics while the correct owner disposition changed after minimum-notional/execution-suitability evidence arrived.

These are Media mediation laws, not transfers of Runtime/Web/Finance authority.

## 8. Phase-1 closure was itself a research result

After M0–M4, the correct next action was **not** to manufacture more fixtures or build a universal framework.

Phase 1 closed because Media had:

- recoverable project identity;
- frozen research authority;
- explicit owner boundaries;
- a falsifiable reference contract;
- heterogeneous conformance evidence;
- retained Studio product continuity;
- no demonstrated cross-consumer implementation duplication requiring shared code.

Therefore the project entered:

`STABLE_OWNER / CONSUMER_PRESSURE_DRIVEN`.

Anti-rediscovery guard:

`NoAutomaticMediaPhase2Backlog`.

Reopen only from real pressure: a failing consumer, a missing Derived Media relation, repeated equivalent implementation machinery, a real Studio production constraint, or Foundation-level counterevidence.

## 9. What to check before reopening Media research/engineering

Before opening a fresh route, ask:

1. Is the alleged new concept already a Derived Media profile or typed composition?
2. Is the truth actually owned by Game, Web, Runtime, Human, Finance, World, Network, SCD, Normative or another owner?
3. Is the problem a projection/legibility/currentness/trajectory issue already covered by OMPC?
4. Does the proposed engineering abstraction respond to repeated implementation duplication, or only repeated conceptual relevance?
5. Is the proposed Foundation candidate irreducible under MF0–MF9 and cross-owner subtraction?
6. Has the Media source fence advanced beyond this synthesis (`5b5dbb4145ca91b575e517b6d56fe119f0853a18`)? If yes, revalidate owner truth first.
