## 1. The result semantics that must not collapse

The strongest surviving map is orthogonal rather than a maturity ladder.

### Lifecycle / production

- `Done / Completed` means execution or continuity lifecycle closure only.
- `Output` means a produced artifact, trace, document, model output, code change, or other produced object.

### Reality / epistemics / direction

- `Outcome` is a realized observed consequence and may be desired, adverse, or null.
- `Standing` is what current evidence supports under a declared scope/source/currentness boundary.
- `Progress` is movement toward a declared target without requiring threshold closure.

### Achievement

Two deletion-essential achievement forms survived:

- `ObjectiveAchievement` — the result satisfies or materially closes a declared objective, decision predicate, or uncertainty predicate.
- `DiscoveryAchievement` — an unplanned but independently standing-supported consequential gain.

`Success` need not be a new primitive; it is derived from a declared objective/criterion and the relevant achievement standing.

### Comparative claims

`Improvement` is pairwise and scope-relative. A valid comparison requires a declared comparison scope `Theta`, including the relevant target/decision family, Reality/evidence bridge, constraints/resource envelope, horizon, protected consequences, and recovery/future-option assumptions.

Partial-order dominance can establish improvement without scalarizing every value dimension.

`Optimality / Optimization` is stronger: it is relative to a feasible/search envelope and an explicit optimality notion. Without a justified feasible set, the strongest safe standing is not global optimality.

Therefore:

```text
MetricGain != Improvement != Optimality != SystemImprovement
LocalOptimality != SystemImprovement
```

There is no universal open-world optimum.

### Future value and downstream use

- `ProspectiveValue` is a future consequence/option relation under a declared future family.
- `Consumption` is actual downstream use by a named consumer/use contract.
- `RealizedBenefit` requires an observed beneficial downstream consequence with adequate attribution standing.

Therefore:

```text
Value != Consumption != RealizedBenefit
```

A static `REALIZED_BENEFIT=true` Result label is generally too weak: beneficiary, observed consequence, scope/horizon, evidence/currentness and attribution standing can all change the truth of the claim.

## 4. Materialization is a role, not a mandatory destination

Research need not become code, schema, service, paper, product, or public surface merely because it is mature.

Four deletion-essential physical/system materialization roles survived current evidence:

- `R1 ConsequenceRepair` — change the system because an existing consequence/failure is wrong and the repair changes that consequence.
- `R2 EpistemicApparatus` — build an instrument, fixture, benchmark, experiment, measurement path, or other apparatus required to learn what is not yet known.
- `R3 ControlBoundary` — materialize a guard/admission/currentness/authority/control distinction because deleting it permits an incorrect or unsafe action.
- `R4 PersistenceRecovery` — preserve an otherwise deletion-vulnerable result, identity, option, source fence, or recovery path when losing it would cause material rediscovery or unsafe reconstruction.

`Product / Direction` is a decision disposition, not a fifth materialization role.

A semantic/default-judgement change, experimental plan, option/reopen retention, product/direction decision, explicit `NO_OP`, or no demonstrated consumption can all be legitimate dispositions without forcing R1–R4.

Important law:

```text
MaterializeToLearn != DeployConclusion
```

Building R2 apparatus does not establish that the investigated theory, product direction, or intervention is correct.

## 5. Admission is conjunctive, not scalar

A proposed materialization should be admitted only when the named consumer/use case can justify the relevant conjunction, such as:

1. exact claim/result and role binding;
2. claim-appropriate current standing and source fence;
3. a named consumer, consequence, uncertainty, or recovery requirement;
4. incremental/deletion-essential need rather than aesthetic completeness;
5. correct semantic owner and authority boundary;
6. falsifiable acceptance evidence;
7. protected consequence/option/resource envelope;
8. the narrowest sufficient intervention.

No universal conversion score follows from these conditions.
